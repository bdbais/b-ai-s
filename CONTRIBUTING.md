# Contribuire a B-AI-S / Contributing

Grazie di essere qui! 🙌 *Thanks for being here!*

Ogni contributo conta: un'idea, una critica, una correzione di battitura, un driver, un dataset, un test su hardware reale.
*Every contribution counts — an idea, a critique, a typo fix, a driver, a dataset, a real-hardware test.*

Si può scrivere in **italiano o in inglese**. *Italian or English are both fine.*

## Modi di aiutare / Ways to help

- 💡 **Idee** — apri una issue con il modello "Idea" o una Discussion. Nessuna idea è troppo strana.
- 🗣️ **Domande aperte** — rispondi o critica una delle [domande aperte](docs/DOMANDE-APERTE.md).
- 🛠️ **Codice** — scegli una issue con etichetta `good first issue` o `help wanted`, commenta per prenotarla, poi apri una pull request.
- 🧪 **Test** — prova il kernel in QEMU, Bochs o su hardware reale e racconta cosa succede.
- 📚 **Documentazione e traduzioni.**
- 🧠 **Dati** — frasi di esempio per il classificatore di intenti, in qualunque lingua.

## Come proporre una modifica / How to propose a change

1. Fai un fork e crea un branch descrittivo (`feature/uefi-boot`, `docs/manifesto-es`).
2. Mantieni le modifiche piccole e focalizzate.
3. Per il codice Rust: `cargo fmt` e `cargo clippy` puliti; spiega come hai verificato (es. comando QEMU).
4. Apri la pull request descrivendo **cosa** cambia e **perché**.

Per cambiamenti grandi (architettura, nuove tappe) apri prima una Discussion: decidiamo insieme.
*For big changes, open a Discussion first so we can decide together.*

## Principi da rispettare / Guiding principles

Ogni contributo dovrebbe essere coerente con il [Manifesto](docs/MANIFESTO.md), in particolare:
- **locale prima di tutto** — nessuna dipendenza obbligatoria dal cloud;
- **chiede prima di agire** — niente autonomia senza consenso;
- **piccolo e comprensibile** — preferire la chiarezza all'astuzia.
